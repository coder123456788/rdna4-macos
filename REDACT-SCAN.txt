REDACT-SCAN.txt

Why this file exists: the owner's binding rule is that the machine's real
serial, MLB, system UUID and ROM (and anything else that identifies the
hardware) must not be published. config.diff.md and logs/INDEX.md quote those
values only in masked form; this file is the proof that the masking held and
that no unmasked copy survived anywhere in the package. It was run last:
every other file here, MD5SUMS included, was written before it.

How to read it: each block is one recursive grep over the whole of
D:\Work\gate1\ship\. Hits are printed as file:line with the line content
suppressed, because a scan report that quotes the string it searched for would
itself be the leak. A hit is not automatically a leak — "<key>MLB</key>" is a
key name, the all-zero UUID is a placeholder — so each block carries
a verdict, and the closing summary counts only the leaks.

The patterns that matter (P1-P7) are the real values taken from
E:\EFI\OC\config.plist. They are not reproduced here, for the same reason the
values themselves are not; they are identified only by their masked prefixes so
that a reader can confirm what was searched for. Anyone re-running the scan can
rebuild the patterns from their own copy of the stick config.

Identities under scan (first 4 characters only):
  serial          F5KC...
  MLB             F5K0...
  system UUID     BDF3... (dashed and undashed forms)
  ROM as stored   vPzn... (base64, 6 bytes)
  ROM as bytes    the 6-byte MAC-shaped value: colon, dash, dot, space and bare
                  hex, both cases, and byte-reversed

VERDICT KEY:
  LEAK  an unmasked real value — must be fixed before push
  KEY   the word SerialNum / MLB / SystemUUID / ROM / MACAddress / HardwareModel
        used as a key name or in prose — carries no identity
  PH    a placeholder we put there ourselves (all-zero UUID, 000000000000 ROM,
        C02TEST027J1, C027J1027J1)
  PATH  a device path — a leak only if it names an internal disk
